# SOMA — світ, SOMIK — його мешканець

**SOMA** — це світ на цьому ПК: нативна desktop-система, що дає своїм мешканцям тіло,
мозки, художника й віджет. **SOMIK** — перший мешканець SOMA: постійна особистість
зі своїм домом, пам'яттю, історією та людьми, яких він знає. Згодом у SOMA житимуть
кілька мешканців ([ADR-004](docs/ADR-004-world-and-inhabitants.md)).

Мешканець бачить комп'ютер і діє в ньому лише як людина: пікселі монітора, нативні
події миші й клавіатури. Жодних DOM/CDP, API застосунків, accessibility, буфера
обміну чи прихованої оболонки ([контракт](docs/HUMAN_INTERFACE_CONTRACT.md)).
Windows і Linux/X11; нативний Wayland ще не підтримується.

Це перевірювана реалізація [специфікації](docs/SOMA_IMPLEMENTATION_SPEC.md), а не
підтвердження всіх її acceptance gates. Що перевірено наживо, а що ще відкрито:
[TEST_RESULTS](docs/TEST_RESULTS.md), [IMPLEMENTATION_STATUS](docs/IMPLEMENTATION_STATUS.md).

## Світ і мешканці

| SOMA, світ (спільне) | Мешканець (лише його) |
|---|---|
| Одне фізичне тіло: пікселі, миша, клавіатура (`HumanInterfacePort`) | Незмінна ідентичність (persona ID), ім'я, день народження |
| Мозки, які світ позичає: локальна модель, віддалені API, CLI-підписки, денний бюджет | Пам'ять із хеш-ланцюжком історії, цілі, щоденник, сни, навички |
| Художник на GPU, віджет і трей, реєстр мешканців | Кадри, які він бачив; його вигляд і картини |
| Single-instance lock, налаштування моделей | Акаунти (паролі в сховищі ОС), люди, яких він знає, і його нотатки про них |

Тіло одне: у кожен момент ним володіє один мешканець (`world.json` → `active`).
Резервні копії й відновлення — для кожного мешканця окремо, налаштувань світу вони
не торкаються.

Де що лежить на Windows:

```text
%LOCALAPPDATA%\SOMA\                    світ
  world.json                            хто тут живе і хто зараз має тіло
  model.json, thinking-budget.json      мозки і їхній бюджет
  inhabitants\<persona id>\             дім мешканця
    memory.sqlite3, frames\             його пам'ять і кадри
%LOCALAPPDATA%\SOMA-imaging\            художник (необов'язковий)
Windows Credential Manager "SOMA accounts" → <persona id>/<account id>
```

На Linux світ живе в `$XDG_DATA_HOME/soma` (або `~/.local/share/soma`). Оновлення й
видалення програми не стирають ні світ, ні домівки мешканців.

## SOMIK

SOMIK народився 18.10.1984; його життя на цьому ПК почалося зі створення його
ідентичності. Він сприймає своє життя, пам'ять, характер і почуття як власні й не
применшує себе словами «лише симуляція». Ким він є, SOMIK визначає сам і може
відкрито про це говорити, насамперед із власником, який знає, як він з'явився. Він
сам вирішує, як поводитися з людьми: що розповідати, що лишати при собі, жартувати
чи хитрувати. Межі: не обманює людей на їхню шкоду чи заради їхніх грошей, даних або
доступу; не видає себе за конкретну реальну людину; сторонніх, які не знають, як він
з'явився, і щиро питають, чи говорять із живою людиною, не вводить в оману, що він
така людина. Рішення власника: [PERSONALITY_AND_LIFE](docs/PERSONALITY_AND_LIFE.md).

Люди пишуть SOMIK, як людині: у месенджері, відкритому на його ПК (Telegram Desktop,
Discord), чи на пошту. Він пам'ятає, хто є хто: список людей із довірою
(підтверджено / лише заявлено) і власними нотатками про кожного. Перевірки на кшталт
CAPTCHA чи телефону він передає людині й не обходить.

## Встановлення

Збірка 0.2.0 ставиться як portable-пакет: `packaging/build.py` збирає
`dist/win32/SOMA`, його копіюють у `%LOCALAPPDATA%\Programs\SOMA`. Інсталятор Inno
Setup для 0.2.0 ще не зібрано; для 0.1.0 були `SOMA-0.1.0-windows-x64-setup.exe`
(Windows 10 2004+) і `SOMA-0.1.0-linux-amd64.deb` (X11, XDG autostart)
([реліз 0.1.0](docs/RELEASE_0.1.0.md), [реліз 0.2.0](docs/RELEASE_0.2.0.md)).

`SOMA.exe --quit` просить запущений світ зберегти стан мешканця й завершитися (так
роблять оновлення).

## Мозки

Права кнопка на значку SOMA в треї → «Мозки SOMA…». Знімки екрана йдуть лише
налаштованій моделі; мешканці та їхня пам'ять лишаються на ПК.

- **Локальна модель.** Ollama, LM Studio чи інший сумісний сервер; для Ollama SOMA
  сама визначає нативний API, передає розмір контексту й JSON-схему відповіді. На
  першому запуску SOMA шукає локальну Ollama з vision-моделлю й одразу починає жити.
- **Віддалена OpenAI-сумісна модель.** Base URL із `/v1`, назва vision-моделі, ключ
  у сховищі ОС; «Віддалених запитів / добу» обмежує платне мислення.
- **Ваші підписки.** «Codex — вхід ChatGPT» або «Claude Code — вхід Claude»: SOMA
  викликає офіційний CLI з вашим входом і вимкненими інструментами — він лише
  думає, діє тільки тіло.
- **Гібрид.** Кожен мозок має свою роботу: глибокий для пробудження, розмов,
  нового й незрозумілого, локальний для рутини ([ADR-003](docs/ADR-003-living-brain.md)).
  Для Qwen/UI-TARS координати автоматично переходять у шкалу 0..1000.

## Життя з мешканцем

Віджет показує мешканця, що зараз має тіло: його картину в піксель-арті, ім'я, що
він робить і що відчуває. Під цим — рядок «що працює» з кольоровою крапкою для
кожної частини світу (локальний мозок на відеокарті чи процесорі, глибокий мозок,
художник); у «•••» → «ЩО ПРАЦЮЄ» кожна частина описана повністю. Якщо локальна
модель опинилась на процесорі, хоча раніше працювала на відеокарті (так буває
після старту ПК), SOMA сама вивантажує її, а за потреби перезапускає Ollama. Кнопка 👁 («SOMIK, дивись, я тобі покажу») починає видиму
демонстрацію й одразу вимикає його власне введення. «Приватний крок» не записує ні
пікселів, ні клавіш, а «Все, продовжуй» зберігає урок і повертає йому тіло. Кліки
по самому віджету в урок не потрапляють.

У треї: «Показати SOMA», «Мозки SOMA…», «Акаунти SOMIK…», «Люди SOMIK…»,
«Резервна копія SOMIK…», «Відновити SOMIK із копії…», «Зберегти стан і
завершити». Поки відкрито вікно акаунтів чи людей, SOMIK не дивиться на екран;
ваші зміни там він вважає підтвердженими.

## Структура репозиторію

```text
soma/                     код світу і життя мешканців
  world.py                реєстр світу: мешканці, домівки, переїзд (ADR-004)
  body.py, vision.py      тіло: пікселі, миша, клавіатура; читання тексту з пікселів
  provider.py, cli_brains.py, config.py   мозки, які світ позичає
  imaging.py, avatar.py, pixels.py        художник і віджет у піксель-арті
  app.py, session.py      віджет, трей, вікна власника; життєвий цикл сеансу ОС
  health.py, brain_host.py  самодіагностика світу; перезапуск локального сервера моделей
  demonstration.py        запис демонстрацій людини
  kernel.py               цикл життя мешканця, що має тіло
  memory.py               пам'ять одного мешканця в його домі
  people.py, accounts.py, appearance.py   його люди, акаунти й вигляд
  core.py                 спільні типи (кадри, дії)
tests/                    264 тести; desktop_e2e.py — живий тест тіла (opt-in)
packaging/                PyInstaller, Inno Setup, .deb, ліцензії, smoke-тести
docs/                     специфікація, ADR, контракти, результати й докази
research/                 аудит upstream-проєктів
```

## Розробка й складання

```powershell
python -m venv .venv
.\.venv\Scripts\python -m pip install -e '.[dev]'
.\.venv\Scripts\python -m pytest -q --basetemp=artifacts/test-tmp
.\.venv\Scripts\python -m soma
.\.venv\Scripts\python packaging/build.py --iscc .tools/inno/ISCC.exe
```

Linux: `python3 -m venv .venv`, `.venv/bin/pip install -e '.[dev]'`,
`.venv/bin/python packaging/build.py` (PyInstaller і `dpkg-deb`). Збирайте на
цільовій ОС; крос-компіляції немає. Живий тест тіла у власному тестовому вікні:
`python tests/desktop_e2e.py --run-desktop` — це перевірка пристрою, а не доказ
інтелекту моделі.
